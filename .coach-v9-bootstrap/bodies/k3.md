## Scope

### In Scope

This issue absorbs `apply_canonical_name_and_layout` from `commands/orchestrate.py` into a coach module so `atdd spawn` (`#K1`) applies canonical naming and layout immediately after the multiplexer surface is created. Per spec §7.1.5 and §0.2 absorption inventory, the helper moves with no behavioral change.

- **Move `apply_canonical_name_and_layout`** into a coach module — e.g. `src/atdd/coach/utils/session_naming_apply.py` — preserving today's behavior verbatim. The function continues to call `compute_canonical_name(repo_short, issue_number, slug)`, `target_grid_label(surface_count)`, and the multiplexer rename + `/rename` injection.
- **`atdd spawn` calls the helper** after `new_workspace`/`new_surface` returns. The call sequence: (1) compute canonical name via `compute_canonical_name`; (2) rename the multiplexer surface (e.g. `cmux rename-tab`); (3) send `/rename <canonical_name>\n` into the running agent so the in-conversation header matches; (4) print the target grid layout via `target_grid_label(surface_count)`.
- **Best-effort behavior preserved** — rename failures don't crash the spawn flow. Per spec §7.1.5 + §8.3, observer rule `14-canonical-naming-drift` (in `wagon:observe-and-correct`) re-applies on subsequent ticks. K3 logs the failure with the `coach.orchestration.canonical-session-name` rule-ID so the observer can correlate.
- **Rule-ID emission** — the rename action emits the `coach.orchestration.canonical-session-name` rule-ID. The layout label emits `coach.orchestration.layout-conformance` per spec §0.1 inventory.
- **Unit tests against a fake multiplexer backend** — exercising the happy path (successful rename), the `/rename` injection capture, the layout label print, and the rename-failure best-effort path.

### Out of Scope

- The observer rule `14-canonical-naming-drift` itself — owned by `#L4` (babysit-absorbed observer rules). K3 emits the rule-ID at spawn time; L4 listens for drift on subsequent ticks.
- The `compute_canonical_name`, `target_grid_label`, and `is_canonical_name` primitives in `session_naming.py` — already shipped per spec §0.1; K3 calls them but does not modify them.
- `atdd spawn` CLI surface — owned by `#K1`. K3 only adds the post-launch naming pass that K1's spawn calls into.
- The substrate spawn-harness blocks — owned by `#K2`. K3 happens after the launch prompt is rendered and the surface is created.
- Multiplexer-backend differences (cmux vs zellij vs tmux) — handled by the existing `multiplexer.py` abstraction; K3 calls the backend-agnostic interface.

### Dependencies

- `#K1` — `atdd spawn` is the call site; K3's helper has no direct entry point of its own.
- `src/atdd/coach/commands/orchestrate.py::apply_canonical_name_and_layout` — the source-of-truth implementation being absorbed (per spec §0.2).
- `src/atdd/coach/utils/session_naming.py::compute_canonical_name`, `is_canonical_name`, `target_grid_label` — existing primitives (per spec §0.1, issue `#470`).
- `src/atdd/coach/utils/multiplexer.py` — existing abstraction whose backends K3 invokes.
- Rule-ID `coach.orchestration.canonical-session-name` — already shipped per spec §0.1; K3 emits it.

## Context

### Problem Statement

| Aspect | Current | Target | Issue |
|--------|---------|--------|-------|
| Canonical naming pass call site | Lives in `commands/orchestrate.py` and is reachable only from `atdd orchestrate` | Lives in a coach module and is reachable from `atdd spawn` | Per spec §0.2 absorption inventory, the orchestrate function must absorb into coach so that the orchestrate decommission (`#P5`) can land without losing canonical-naming behavior |
| `/rename` header injection | `atdd orchestrate` injects `/rename <canonical_name>\n` into the running agent's stdin | `atdd spawn` injects identically | Without identical injection, in-conversation headers (visible to operators in the multiplexer) drift from surface names, breaking the operator's ability to scan the dashboard |
| Best-effort failure handling | Today's helper catches and logs rename failures so orchestrate doesn't crash | K3's helper preserves the catch-and-log discipline; observer rule `14` re-applies on drift | Tightening this to fail-hard would crash spawns whenever a multiplexer backend transient occurs; loosening it to silent-discard would lose the observer hook |
| Rule-ID emission on rename | Today emits `coach.orchestration.canonical-session-name` per spec §0.1 | Coach v9 absorbs the same rule-ID emission | Per spec §0.1, the rule-ID is the substrate's hook for observer drift detection; preserving it preserves the L-track observer rule's ability to bind |

### User Impact

The "user" of this issue is the operator who scans the multiplexer dashboard for which session belongs to which issue, and the observer that re-applies naming on drift. Per spec §7.1.5, the canonical name pattern is `FORGE<issue-number>-<persona>` (e.g. `FORGE358-coder`); without K3, sessions launched via `atdd spawn` keep whatever default name the multiplexer backend assigned (e.g. `tab-3`), and the operator has to manually correlate.

Per spec §0.2 absorption inventory, the function being absorbed is the literal one in `commands/orchestrate.py` today. The absorption preserves behavior verbatim — same `compute_canonical_name` call, same `/rename` injection bytes, same `target_grid_label` invocation, same try/except shape around the rename call. The operator-visible behavior should be indistinguishable between today's `atdd orchestrate` and tomorrow's `atdd spawn` for naming purposes; the parity suite (`#K5`) enforces this.

The lived pain today: when the v8 coach prototype skipped the naming pass (because it was buried in orchestrate's launch flow), operators saw multiplexer dashboards with mixed `FORGE358-coder` (orchestrate-launched) and `tab-3` (prototype-launched) entries. Identifying the right session for a given issue required reading the launch prompt — a slow, manual cross-reference. K3 closes this gap.

### Design Anchor

The "best-effort" discipline is not a design choice K3 invents; it's a discipline today's `apply_canonical_name_and_layout` already encodes, motivated by the same constraint coach v9 has (multiplexer backends fail transiently; the observer can re-apply). K3 preserves it verbatim so behavior parity holds.

The choice to move the function into a coach module (rather than coach calling into `commands/orchestrate.py` directly) reflects spec §11.3's decommission plan: orchestrate's module is removed in `#P5`, so any function coach depends on must move first. K3 is one such move; `#J4` (two-phase commit) is another. Per spec §0.2, the absorbed-function set is documented up front so each absorption issue knows its scope.

## Acceptance

- `acc:spawn-agents:E002-UNIT-001-canonical-name-applied`: After `atdd spawn` returns, the multiplexer surface has the canonical name (e.g. `FORGE358-coder`) computed via `compute_canonical_name(repo_short, 358, slug)`; the fake multiplexer backend records exactly one rename call against the launched surface; the `coach.orchestration.canonical-session-name` rule-ID is emitted on the rename action.
- `acc:spawn-agents:E002-UNIT-002-rename-injected-into-agent`: Exactly one `/rename <canonical_name>\n` line is sent into the launched session's stdin (captured by the fake backend); the canonical_name value matches the surface rename target from AC-UNIT-001.
- `acc:spawn-agents:E002-UNIT-003-layout-label-printed`: stdout contains the `target_grid_label(N)` string for the surface count `N` after spawn.
- `acc:spawn-agents:E002-UNIT-004-best-effort-on-rename-failure`: When the fake multiplexer backend is configured to raise on rename, `atdd spawn` returns successfully; the rename failure is recorded as a log line referencing `coach.orchestration.canonical-session-name`; the `agent_spawned` event is still emitted (E001 contract holds independently).

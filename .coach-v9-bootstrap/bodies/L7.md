## Context

### Problem Statement

| Aspect | Current | Target | Issue |
|--------|---------|--------|-------|
| Cross-surface batch approval | `aggregate_approve` ships in babysit and approves matching prompts across active multiplexer surfaces in one action | Same logic in `atdd observer aggregate-approve` reading from observer-tracked sessions | Without absorption, decommissioning babysit forces operators to approve safe prompts surface-by-surface |
| Scope filtering | `--scope` (or equivalent) restricts the action to named issues' sessions | Same flag at parity | Operators with many concurrent issues need this to avoid batch-approving outside their intended scope |
| Bash-pattern source | The patterns file at `orchestration.convention.yaml::babysit.bash_auto_approve_patterns.rules` is the canonical safe-list | Shared read path with rule 13 (#L4) | Without a shared read path, rule 13 and aggregate-approve can drift; with it, both are fed by the same convention edit |

### User Impact

The "user" is the coach operator running multiple simultaneous coach-orchestrated agents that hit the same auto-approvable bash prompt at the same time. Today, the operator runs `atdd babysit aggregate-approve` once and unblocks every surface; tomorrow, the same operator runs `atdd observer aggregate-approve` and sees the same outcome. Per spec §5.4, this is one of the three operator surfaces the observer command exposes (alongside `status` and `attach`).

The lived observation: when several agents hit a tool prompt covered by `babysit.bash_auto_approve_patterns` but blocked by an outer permission scope, surface-by-surface approval is operationally painful. Rule 13's per-prompt auto-approval handles the common case; aggregate-approve handles the cross-surface case. The two together preserve babysit's UX surface fully.

### Root Cause

Babysit's `aggregate_approve` is structured around polling a multiplexer for surfaces awaiting approval. Coach v9's runtime layout makes the surfaces enumerable from `.atdd/runtime/agents/*/` instead. The function's predicate-and-batch-action shape is preserved; only the surface-enumeration source changes.

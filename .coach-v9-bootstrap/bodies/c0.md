## Scope

### In Scope

This is the coordination prerequisite for all parallel coach v9 tracks. Six agents working simultaneously need stable schemas for the artifacts they produce and consume. Without explicit contracts, every cross-track interface is a potential merge conflict, and divergent temporal assumptions surface only at the #Q1 integration step.

Produces a documentation-and-schemas-only PR (no behavior) at `src/atdd/coach/schemas/`:

- **`runtime-event.schema.json`** — every event type the runtime watcher emits (#J5 produces, #L1/#M1 consume). Event types: `agent_spawned`, `heartbeat`, `commit_observed`, `event_emitted`, `escalation_emitted`, `pr_opened`, `pr_closed`, `validation_pending`, `validation_complete`, `review_complete`, `correction_emitted`, `process_silence`. Each has shape `{event_type, agent_id?, timestamp, payload: {...}}`.
- **`coach-decision.schema.json`** — formalized from #J3 spec text. Append-only entries for `decisions.jsonl` (state transitions, configuration choices, escalations). Required fields: `decision_id`, `timestamp`, `coach_run_id`, `issue_number`, `decision_type`, `inputs`, `outcome`.
- **`coach-judgment.schema.json`** — formalized from #J3. Append-only for `judgments.jsonl`. Required: `judgment_id`, `timestamp`, `call_site` (one of the six per spec §6.9), `inputs_hash`, `response`, `cached` (bool).
- **`correction.schema.json`** — observer correction payloads (#L1 produces, #J5 consumes). Fields: `agent_id`, `rule_id`, `severity`, `disposition`, `correction_text`, `injection_method` (cli-return/multiplexer-send/respawn).
- **`validator-result.schema.json`** — formalized from spec §7.5. Aligns with substrate's `Violation` dataclass. Fields: `validator_id`, `rule_id`, `severity`, `disposition`, `location`, `detail`, `suppression_marker`. Used by #M2 (writer) and #N2/#O2 (readers).
- **`risk-score.schema.json`** — risk score per phase exit (spec §6.8). Fields: `sum`, `by_severity`, `by_archetype` (incl. `repo` slice), `by_disposition`, `stale_suppressions`. Written to `validations/<sha>/risk-score.json`.
- **`runtime-layout.md`** — the directory/file structure under `.atdd/runtime/` documented as a contract: `agents/<id>/heartbeat.json`, `agents/<id>/output.log`, `agents/<id>/events.jsonl`, `agents/<id>/corrections.jsonl`, `coach/decisions.jsonl`, `coach/judgments.jsonl`, `validations/<sha>/violations.jsonl`, `validations/<sha>/risk-score.json`, `validations/<sha>/suppressed.jsonl`, `validations/<sha>/stale-suppressions.jsonl`. Each file's role, who writes, who reads, append-only or rewritten, JSON-line vs single-doc.
- **`validator-invocation.md`** — how coach invokes the substrate pytest plugin. Fields: pytest CLI flags, `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` policy, timeout per phase, retry-on-subprocess-crash policy (vs test-failure — different signal handling), env vars passed through.
- **`event-semantics.md`** — temporal contracts for every event type defined in `runtime-event.schema.json`. Schemas freeze *shape*; this document freezes *semantics*. For each of the 12 event types, specify: producer, triggering condition, idempotency contract (at-least-once vs exactly-once), ordering guarantees (per-agent total / cross-agent partial / none), replay behavior on `--resume`. Without this artifact, parallel tracks would each form different temporal assumptions; concurrency bugs would surface only at #Q1.

Each JSON Schema gets at least one valid example fixture committed alongside at `src/atdd/coach/schemas/fixtures/<schema-name>/`. A CI job validates that any future PR touching the schema files updates the corresponding fixtures.

Note: schemas reference but do NOT redefine substrate's `Violation` and `RuleMetadata` (they are stable Python dataclasses with established contracts). C0 is the boundary at which coach-internal artifacts are formalized.

### Out of Scope

- Implementing any of the producers/consumers (#J5 watcher, #M1 git watcher, #L1 observer correction injection, #M2 pytest plugin, #N2 review-report writer). C0 freezes the contracts; execution lives in the downstream track issues.
- Redefining substrate dataclasses (`Violation`, `RuleMetadata`). Those are stable; coach references their established contracts.
- Adding new event types beyond the 12 enumerated in spec §C0. Extension goes through an explicit proposal in a follow-up issue.
- Wiring schemas into a runtime validator inside coach (#J3, #M2 own that integration).
- The `.atdd/coach/config.yaml::coach.*` block schema (#P4 owns config-loader extensions).

### Dependencies

- None — C0 is the entry point of the coach v9 implementation. All other tracks depend on it.

## Context

### Problem Statement

| Aspect | Current | Target | Issue |
|--------|---------|--------|-------|
| Coach-internal artifact contracts | Six tracks would each invent their own producer/consumer shapes during parallel execution | All six artifact schemas + three contract docs frozen at `src/atdd/coach/schemas/` before any track ships code | Without C0, every cross-track interface is a potential merge conflict; integration bugs surface only at #Q1 |
| Runtime event temporal semantics | No shared contract for producer / triggering condition / idempotency / ordering / replay across the 12 event types | `event-semantics.md` enumerates these for each of the 12 types | Parallel tracks would form divergent temporal assumptions; concurrency bugs (duplicate suppression, replay re-fire, watcher reattachment) surface at integration not at unit-test time |
| Validator invocation surface | `atdd validate` has implicit pytest invocation conventions; coach must reuse them under different timeout/retry constraints | `validator-invocation.md` documents flags, autoload policy, timeouts, subprocess-crash vs test-failure handling, env passthrough | Without it, #M3's per-phase dispatch logic would each rediscover the constraints |
| Runtime directory layout | Spec §3.2 lists the layout in prose; agents under coach orchestration need a contract they can verify against | `runtime-layout.md` enumerates each path with role/writer/reader/appendability/serialization-shape | Without it, sidecar files (#L1, #M1, #J3) drift in shape and discoverability |

### User Impact

The "user" of this issue is every coach v9 implementer and downstream consumer of the runtime artifacts. C0 is the artifact contract that makes parallel implementation possible: per spec §11.1, Tracks J/K/L/M/N/O/P all start in parallel after C0 lands, with no schema-shape conflicts because everything was agreed up front. Today this contract does not exist; without it, the parallel-tracks model in §11.1 collapses into serial work or merge-time conflict resolution.

The lived problem: `atdd orchestrate` and `atdd babysit` evolved as a "fixed handful of patterns" (`detect_violation`, `BashPattern`, `_screen_hash`) without an explicit contract. Coach v9 deliberately replaces that pattern with extensible observer rules, durable state, and event-driven dispatch — but those amplifiers require a stable artifact substrate. C0 is that substrate.

Per spec §6.4 step 4, validators write `Violation` records via a custom pytest plugin (`coach.runtime.violation_collector`) that writes to `validations/<sha>/violations.jsonl`. Per §6.8, risk score writes to `validations/<sha>/risk-score.json`. Per §6.10, issue review aggregate writes to `issue-reviews/<issue-N>/aggregate.json`. Each of these files becomes a contract; C0 freezes the contracts.

### Design Anchor

C0 sits at the boundary between "shipped substrate" (substrate v12: `Violation`, `RuleMetadata`, `bind_rule`, `disposition_gate`, suppression scanner) and "coach v9 internals" (decisions, judgments, corrections, runtime events, risk scores). The substrate's contracts are stable; coach v9 introduces new artifacts that span all six parallel tracks. By freezing the new contracts at the substrate boundary — and explicitly NOT redefining substrate dataclasses — C0 keeps the layering clean and the integration surface narrow.

The architecture choice "schemas freeze shape, docs freeze semantics" (with `event-semantics.md` complementing `runtime-event.schema.json`) reflects the v3-spec rationale: shape-only schemas would not catch divergent temporal assumptions across the 12 event types. The combination is what unblocks #Q1 from being a hidden-bug minefield.

- `acc:freeze-runtime-contracts:D002-UNIT-001-runtime-layout-doc-committed`: `src/atdd/coach/schemas/runtime-layout.md` is committed and reviewed-and-approved by all track owners (J1, K1, L1, M1, N1, O1, P1) before merge; every file path under `.atdd/runtime/` enumerated in spec §3.2 is documented with role, writer, reader, append-only-vs-rewritten, and JSON-line-vs-single-doc; the document references the JSON Schemas it complements by relative path.
- `acc:freeze-runtime-contracts:D003-UNIT-001-validator-invocation-doc-committed`: `src/atdd/coach/schemas/validator-invocation.md` is committed and specifies: the pytest CLI flag set coach uses to invoke validators; the `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` policy with rationale; per-phase timeout defaults and override mechanism; the retry-on-subprocess-crash policy explicitly distinguished from retry-on-test-failure (different signal handling); the env-vars passed through to validator subprocesses.
- `acc:freeze-runtime-contracts:D004-UNIT-001-event-semantics-doc-complete`: `src/atdd/coach/schemas/event-semantics.md` is committed and reviewed-and-approved by all track owners; every one of the 12 event types has its own subsection specifying producer, triggering condition, idempotency contract (at-least-once vs exactly-once; whether consumers must dedupe), ordering guarantees (per-agent total order, cross-agent partial order, or none), and replay behavior (does the event re-fire on `coach --resume`; cached; idempotently re-applied).

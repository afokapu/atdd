## Scope

### In Scope

L3 implements observer rule `06-token-threshold` per spec §8.3 by absorbing three functions from `commands/babysit.py` verbatim into a coach observer module:

- `load_token_alert_threshold` — reads `coach.token_alert_threshold` from `.atdd/config.yaml` (default 400000 tokens per spec §10).
- `read_token_count` — runs `claude --print-context-status` (or persona-specific equivalent) and parses the token count.
- `check_token_threshold` — compares current token count to threshold; returns whether the alert should fire.

The rule itself ships at `.atdd/observer/rules/06-token-threshold.yaml`. On evaluation:
- The rule loads the threshold via the absorbed `load_token_alert_threshold`.
- It reads the current token count via the absorbed `read_token_count`.
- On threshold breach, it emits a correction with text `Approaching context limit. Run /compact.` per spec §8.3.
- The injection_method is `cli-return` per the L1 default.

Behavior parity with babysit is required and asserted by unit tests against fixture token-count readings spanning above, at, and below the threshold. The default 400k threshold is preserved; configuration override at `coach.token_alert_threshold: <N>` lowers (or raises) the firing threshold accordingly per spec §10.

Rule-IDs introduced: `06-token-threshold` (canonical rule_id resolved via `bind_rule()`). Schemas conformed to: `correction.schema.json` from #C0.

Files touched:
- `.atdd/observer/rules/06-token-threshold.yaml` — rule declaration.
- `src/atdd/coach/commands/observer.py` (or sibling module) — absorbed function definitions.
- `commands/babysit.py` — functions moved out (#L3 removes the function bodies but does NOT delete `commands/babysit.py` itself; #P6 owns the decommissioning).

### Out of Scope

- The other 16 default observer rules (#L1, #L2, #L4, #L5).
- Decommissioning `atdd babysit` from the CLI surface — #P6 owns that, gated on the parity test suite from #L8.
- The dashboard and aggregate-approve absorbings — those are separate babysit-absorbing issues at #L6 and #L7.
- Changes to the threshold semantics or default value — this issue absorbs verbatim. Any future tuning of the 400k default is a separate proposal.

### Dependencies

- `#L1` — observer skeleton and rule registry.
- Existing repo: `commands/babysit.py` `load_token_alert_threshold`, `read_token_count`, `check_token_threshold`; `.atdd/config.yaml` `coach.token_alert_threshold`.

## Context

### Problem Statement

| Aspect | Current | Target | Issue |
|--------|---------|--------|-------|
| Token-threshold alerting | `commands/babysit.py` owns `load_token_alert_threshold`, `read_token_count`, `check_token_threshold` and runs them inside the babysit polling loop | Same three functions live in a coach observer module and run inside the L1 evaluation loop as rule `06-token-threshold` | Without absorption, decommissioning babysit (#P6) deletes a working capability; with absorption, behavior is preserved verbatim |
| Threshold configuration | `coach.token_alert_threshold` (default 400000) | Same key, same default — coach reads it via the absorbed loader | Operator-facing config is unchanged |
| Behavior parity gate | Babysit decommissioning would today regress token alerting if not absorbed | Parity is asserted in the #L8 test suite, which gates #P6 | Without #L3, #P6 cannot land safely |

### User Impact

The "user" is every coach-orchestrated agent whose context window approaches saturation. Today, babysit alerts the agent to run `/compact`; tomorrow, observer rule 06 does the same. From the agent's perspective the correction is identical; from the architecture's perspective the signal moves from a polling loop to the event-driven observer. Per spec §0.2, this is the canonical absorption pattern: "Token-count alerting (`load_token_alert_threshold`, `read_token_count`, `check_token_threshold`; default 400k). **Absorbed** as observer rule `06-token-threshold`."

The lived observation: token-window exhaustion is one of the two most common silent-failure modes for long-running coach sessions (the other is process silence, covered by rule 02 in #L2). Without rule 06, the agent saturates and produces degraded output; with it, the agent gets a structured prompt to compact and recover. That capability is not new — it ships in babysit today — but it must move with the decommissioning, not against it.

Per spec §11.3, decommissioning (`#P5`, `#P6`) is gated on parity tests (`#K5`, `#L8`). #L3 is one of the absorbing issues that makes #L8's parity assertion possible.

### Root Cause

Babysit's polling-loop architecture binds the token-threshold alert to a poll-tick-driven dispatcher (`process_workspace`, `_screen_hash`). Coach v9's event-driven model needs the same threshold-checking machinery on a different dispatcher — the L1 evaluation loop. The absorption strategy preserves the threshold-checking functions while changing only their caller.

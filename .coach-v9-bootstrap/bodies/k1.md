## Scope

### In Scope

This issue stands up the K-track entry point: one rule-IDed launch surface that every coach v9 persona (planner, tester, coder, reviewer) flows through, replacing the ad-hoc shell-out paths that exist today between `atdd orchestrate`, `atdd coach`, and operator hand-typing.

- **`src/atdd/coach/commands/spawn.py`** — new module registering the `atdd spawn` CLI per spec §5.2 with the full required flag set: `--persona <planner|tester|coder|reviewer>`, `--llm <claude-code|codex|gemini|glm|...>`, `--worktree <path>`, `--issue <number>`, `--agent-id <unique-id>`, `--runtime <path-to-.atdd/runtime>`, plus optional `--phase`, `--target-commit`, `--prior-attempt`, `--multiplexer-ref`.
- **Wraps `session_template.py::render`** — the existing rendering primitive (referenced in spec §0.2 absorption inventory) — and writes the output to `<worktree>/.launch_prompt.txt`. The harness section blocks (`wmbt_rules:`, `train_rules:`, `security_rules:`) are added in `#K2`; this issue establishes the wrapper pathway.
- **Multiplexer dispatch** via the existing abstraction at `src/atdd/coach/utils/multiplexer.py` — calls `get_multiplexer`, then `new_workspace` or `new_surface` per the multiplexer mode. Surface ref is returned and logged.
- **Adapter selection** keyed off `--llm`. K1 ships the `claude-code` adapter, which shells out to `claude --dangerously-skip-permissions "$(cat <prompt>)"` against the rendered launch prompt. Codex, gemini, and glm adapters land as separate K-track follow-ups using the same dispatch shape.
- **Emits an `agent_spawned` runtime event** to the configured runtime path, conforming to the `runtime-event.schema.json` frozen by `wagon:freeze-runtime-contracts` (`#C0`). Producer/triggering-condition/idempotency/ordering/replay semantics match the `agent_spawned` subsection of `event-semantics.md`.
- **Rule-ID emission** — the spawn flow emits at least one rule-ID (`coach.spawn.atdd-spawn-cli` or equivalent canonical anchor) on each launch so observers can correlate spawn-time decisions with downstream events.

### Out of Scope

- The substrate spawn-harness blocks (`render_wmbt_rules_block`, `render_train_rules_block`) themselves — owned by `#K2`. K1 only stands up the wrapper that K2 plugs into.
- The canonical-naming + layout pass post-launch (`apply_canonical_name_and_layout`) — owned by `#K3`. K1's spawn returns once the surface is created; K3 hooks naming on top.
- Per-LLM convention file generation (CLAUDE.md, AGENTS.md, GLM.md, GEMINI.md) — owned by `#K4` and `#P3` (sync hookup).
- Codex / gemini / glm adapter implementations — separate K-track follow-ups. K1 ships only the claude-code adapter and the dispatch shape.
- Coach-state-machine lifecycle integration (`atdd coach` invoking `atdd spawn` per phase) — owned by `#J1` (state machine) and `#J4` (two-phase commit). K1 is invocable directly from the CLI; coach integration is a thin call.
- Worktree creation — owned by `#J4` (two-phase commit absorbed). K1 assumes `--worktree` points to an already-created worktree.

### Dependencies

- `#J1` — coach state machine skeleton publishes the `atdd coach` entry point that K1's spawn integrates against in later issues.
- `#J2` — `atdd agent` CLI subcommands establish the runtime-event emission surface that the `agent_spawned` event flows through.
- `#C0` — runtime-event schema and event-semantics doc that K1's `agent_spawned` event must conform to.
- `src/atdd/coach/utils/multiplexer.py` — existing multiplexer abstraction (cmux/zellij/tmux backends).
- `src/atdd/coach/commands/orchestrate.py::session_template.py::render` — existing rendering primitive being wrapped.

## Context

### Problem Statement

| Aspect | Current | Target | Issue |
|--------|---------|--------|-------|
| Persona launch surface | Three paths can launch a session today: `atdd orchestrate` (Phase B launch), `atdd coach` direct invocation in the v8 prototype, and operator hand-typed `claude` invocations. Each path renders the launch prompt slightly differently. | One rule-IDed entry point — `atdd spawn` — wraps `session_template.py::render`, dispatches the multiplexer, runs the per-LLM adapter, and emits the `agent_spawned` event. | Without one entry point, the K2 harness blocks, K3 naming pass, and observer rule `14-canonical-naming-drift` have nothing stable to bind against; observer events drift in shape across the three launch paths. |
| Multiplexer dispatch consistency | `apply_canonical_name_and_layout` and `_create_workspace_or_surface` are duplicated between `commands/orchestrate.py` and the v8 coach prototype | Both behaviors flow through one `atdd spawn` call; orchestrate later decommissions per `#P5` | Per spec §0.2 absorption inventory, the launch path is the seam where orchestrate behavior is preserved verbatim and re-exposed under the coach surface |
| Per-LLM adapter dispatch | LLM-specific shell-out lives inline in operator scripts and prototype branches | `--llm` switches dispatch; new LLMs register as separate adapter modules without editing the CLI | Without dispatch separation, every LLM addition would touch the spawn module's CLI surface and risk regression |
| Runtime event conformity | `agent_spawned` is emitted ad-hoc with bespoke fields per launch path | Conforms to `runtime-event.schema.json` (frozen at `#C0`) and the `agent_spawned` subsection of `event-semantics.md` | Per spec §4.4 and §4.5, downstream consumers (`#L1` observer, `#J5` watcher) parse this event and assume schema conformity; an off-shape event corrupts coach state |

### User Impact

The "user" of this issue is every coach v9 implementer who will add a persona, an LLM adapter, or an observer rule that depends on launch-time signals. Today there is no rule-IDed entry point; tomorrow `atdd spawn` is the single seam where launch behavior lives and where downstream tracks bind.

Per spec §5.2, `atdd spawn` is the documented public CLI surface for persona launch. Per §7.1, the harness includes a rule-ID context block that K2 fills in — but K2 cannot ship until K1 stands up the wrapper that calls `render`, writes `.launch_prompt.txt`, and dispatches the multiplexer. Per §7.1.5, the canonical-naming pass is layered on top — K3 cannot ship until K1 returns a surface ref. Per spec §11.3, the orchestrate decommission gate (`#P5`) cannot land until the parity suite (`#K5`) proves equivalence between today's `atdd orchestrate` launch path and the new `atdd spawn` path.

The lived pain today: the v8 coach prototype branch and `commands/orchestrate.py` independently call `session_template.py::render` with subtly different argument orders. When operators run one path locally and the prototype runs the other in CI, identical issues produce non-byte-equivalent `.launch_prompt.txt` files. K1 is the merge point that eliminates this drift before downstream tracks compound it.

### Design Anchor

`atdd spawn` is deliberately a thin wrapper, not a re-implementation. The rendering primitive (`session_template.py::render`), multiplexer dispatch (`get_multiplexer`, `new_workspace`/`new_surface`), and per-LLM shell-out are existing or near-existing surfaces; spawn binds them together under one rule-IDed CLI command. Per spec §2 ("Existing machinery absorbed, not duplicated"), this is the explicit pattern: every primitive that ships today moves into a coach module unchanged in behavior.

The `--llm` dispatch shape mirrors the persona-LLM pattern in `coach.persona_llm.<phase-agent>` from spec §6.3: an LLM is selected per-launch, not baked into spawn. K1 ships claude-code first because today's primary operator workflow uses it; subsequent K-track issues add codex/gemini/glm without editing K1's CLI surface.

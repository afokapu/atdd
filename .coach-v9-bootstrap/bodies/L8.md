## Scope

### In Scope

L8 operationalizes "behavior parity" for the babysit-absorbing issues — #L3 (token threshold), #L4 (bash auto-approve, naming/layout drift, smoke-skip), #L6 (dashboard), #L7 (aggregate-approve) — with a fixture-driven test suite that gates `#P6` (babysit decommissioning) per spec §11.3. Mirrors the discipline of `#K5` (orchestrate parity).

- Create `tests/integration/test_babysit_observer_parity.py`.
- Each fixture defines a babysit invocation against a fake multiplexer state and the expected `atdd observer` equivalent.
- Assert equivalence on observable outputs across **at least seven scenarios**, one per absorbed function category:
  1. **Token-alert firing** — given a fake `claude --print-context-status` output, both fire the alert at the same threshold (#L3).
  2. **Bash-pattern auto-approval** — given a screen with a known-safe prompt, both approve; with a deny pattern, both escalate (#L4 rule 13).
  3. **Naming drift correction** — given a renamed surface, both detect drift and re-apply canonical name within one tick (#L4 rule 14).
  4. **Layout drift correction** — given a non-conforming surface arrangement, both correct it (#L4 rule 15).
  5. **Smoke-skip detection** — given a screen showing `--status REFACTOR` without prior SMOKE, both flag the violation (#L4 rule 16).
  6. **Dashboard rendering** — given a fake set of surfaces, both produce the same row content (modulo trailing whitespace) (#L6).
  7. **Aggregate-approve** — given multiple surfaces with auto-approvable prompts, both approve the same set (#L7).
- Differences that are NOT failures (documented in-repo as a `differences-allowed` list):
  - `corrections.jsonl` additions (coach-side richer logging).
  - Dashboard-format minor whitespace.
  - Internal state representation changes.
- Total wall-clock runtime under 60 seconds on a developer machine.
- CI failure on this suite blocks `#P6` from landing — this gating is documented in the repo's #P6 PR-merge policy.

Labels per the briefing: `coach`, `track-l`, `wave-w3`, `parity-test`, `gating-decommission`.

Rule-IDs: none introduced. Schemas: reads `correction.schema.json` records emitted by both the babysit and observer paths to compare equivalence; reads dashboard table output via captured stdout fixtures.

### Out of Scope

- The detection rules and operator surfaces themselves — those ship in #L1, #L3, #L4, #L6, #L7.
- The orchestrate parity suite — #K5 owns it.
- Decommissioning `atdd babysit` (the `commands/babysit.py` removal, the `atdd babysit` CLI removal) — #P6 owns it. #L8 only provides the gating signal.
- Performance benchmarking — the <60s budget is a developer-experience floor, not a performance contract.

### Dependencies

- `#L1` — observer skeleton (each scenario invokes `atdd observer` end-to-end).
- `#L3` — token-threshold rule (scenario 1).
- `#L4` — bash auto-approve + naming/layout drift + smoke-skip rules (scenarios 2–5).
- `#L6` — dashboard (scenario 6).
- `#L7` — aggregate-approve (scenario 7).
- Existing repo: `commands/babysit.py` (the legacy implementations exercised by the fixtures during the parity window).

## Context

### Problem Statement

| Aspect | Current | Target | Issue |
|--------|---------|--------|-------|
| Decommissioning safety | `atdd babysit` would today be deleted in #P6 with no executable parity check | Parity suite asserts equivalence across all absorbed function categories | Without it, #P6 is a regression risk; with it, decommissioning is gated on a green CI signal |
| Parity drift over time | Even after #L3-#L7 land, future edits to either path could drift | Fixture-driven CI suite re-runs on every PR touching the absorbing modules | Without ongoing CI gating, parity is a one-time check rather than a contract |
| Differences-allowed list | The two implementations have legitimate small differences (e.g., observer's richer corrections.jsonl) that should not be failures | Documented `differences-allowed` list in-repo | Without it, parity assertions either miss real regressions (too lenient) or burn time on cosmetic drift (too strict) |
| Runtime budget | A slow parity suite would discourage running it locally | <60s wall-clock budget on a developer machine | Without a budget, the suite drifts toward "CI-only" and contributors miss regressions before push |

### User Impact

The "user" is every contributor about to land #P6 (babysit decommissioning) and every operator who depends on babysit's current behavior. Per spec §11.3, "CI fails this suite → #P6 cannot land." That is the contract this issue delivers: an executable, fast, and CI-gating proof that the observer's absorbed behavior matches babysit's, scenario by scenario.

After L8 lands, #P6 has a clear green light: the parity suite passes → decommissioning is safe. Future regressions in any absorbing path are caught at PR-time, not at production-time.

The lived observation: babysit has been the operator's daily driver for multi-issue runs. Decommissioning it without a parity check would be operationally disruptive even if the absorbed code is semantically correct. The parity suite is the safety net that makes the architectural transition transparent.

### Design Anchor

L8 mirrors the design of #K5 (orchestrate parity). Both share the same shape: fixture pairs, equivalence assertions on observable outputs, a documented differences-allowed list, a runtime budget, and a CI gating contract for the corresponding decommissioning issue. The mirroring is intentional — the orchestrate and babysit decommissionings (#P5, #P6) are sibling concerns, and their parity gates should look the same so contributors can use one mental model.

The `differences-allowed` list is non-trivial: corrections.jsonl additions are *expected* to differ because the observer logs more than babysit did. Accepting that asymmetry without losing the strict parity on observable behavior is the design challenge. The list is the contract that resolves it.

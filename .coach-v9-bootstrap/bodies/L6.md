## Scope

### In Scope

L6 implements `atdd observer status` per spec §5.4 by absorbing the dashboard rendering machinery from `commands/babysit.py` per spec §0.2:

- `_render_dashboard` — layout/formatting of the per-surface table.
- `SurfaceRow` — value-object for one dashboard row (name, phase, last-heartbeat, token count).
- `_format_hms` — duration formatter.
- `_extract_surface_state` — adapted to read from `.atdd/runtime/agents/*/` (heartbeat.json, token-count metadata, current phase) instead of polling multiplexer state.

The output is at parity with `atdd babysit`'s dashboard at time of decommissioning, modulo trailing whitespace. The data-source migration from multiplexer-polling to `.atdd/runtime/agents/*/` is the architectural change; the rendering itself is preserved.

Files touched:
- `src/atdd/coach/commands/observer.py` — wires up the `status` subcommand body (`run`/`attach` shipped in #L1).
- The four absorbed functions move out of `commands/babysit.py` into the observer module. (#L1 lit up the subcommand stub; #L6 fills it in.)

Rule-IDs: none introduced (this issue is an operator surface, not a detection rule). Schemas: reads `runtime-event.schema.json`-shaped event records and heartbeat/token-count metadata under `.atdd/runtime/agents/*/`.

## Context

### Problem Statement

| Aspect | Current | Target | Issue |
|--------|---------|--------|-------|
| Dashboard rendering | `_render_dashboard` and friends ship in babysit and produce a per-surface table for operators | Same rendering in `atdd observer status` reading from `.atdd/runtime/agents/*/` | Without absorption, decommissioning babysit deletes operator visibility into multi-surface coach runs |
| Data source | Babysit polls multiplexer state directly (`_screen_hash`, `process_workspace`) to derive surface rows | Observer reads from `.atdd/runtime/agents/*/` — heartbeat.json, token-count metadata, current phase | The polling source was lossy and slow; the runtime-directory source is event-driven and authoritative per spec §3.2 |
| Output parity | A regression in row content would surprise every operator using the dashboard daily | Output matches babysit modulo trailing whitespace, asserted by the #L8 fixture-driven parity suite | Without parity, decommissioning is a regression; with parity, it's a transparent substrate change |

### User Impact

The "user" is the coach operator running multi-surface sessions. The dashboard is the primary visibility surface — at-a-glance phase, last-heartbeat, and token-count for every active agent. Per spec §5.4, "`atdd observer status` renders the surface dashboard at parity with today's `babysit` dashboard." The verbatim "at parity" phrasing is the contract this issue delivers against.

After L6 lands, operators run `atdd observer status` instead of `atdd babysit` (which is then decommissioned by #P6) and see the same rows with the same data, sourced from the more reliable substrate. The migration is transparent to the operator.

The lived observation: the babysit dashboard has been the canonical operator surface for multi-issue runs since the orchestrate/babysit pair shipped. It would be a major regression to lose it during decommissioning. #L6 ensures parity is maintained.

### Root Cause

Babysit's dashboard is bound to its polling loop because it derives `SurfaceRow` from raw multiplexer state. Coach v9's runtime-folder layout (spec §3.2) makes the same data available from an authoritative event-driven source. The absorption therefore has two parts: (1) preserve the rendering verbatim, and (2) swap the data-extraction function (`_extract_surface_state`) to read from `.atdd/runtime/agents/*/`.

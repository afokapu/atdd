## Scope

### In Scope

L2 implements seven of the seventeen default observer rules from spec §8.3 — the basic-protocol set that catches structural violations independent of any substrate-rule-id machinery. Each rule lives at `.atdd/observer/rules/<NN>-<slug>.yaml` and runs through the L1 evaluation loop.

- **`01-unstructured-question`** — fires on question patterns outside `atdd agent ask`. Correction: "Reformulate via `atdd agent ask --type ...`."
- **`02-token-silence`** — fires when no tokens have been observed for >90s (default per spec §10 `observer.activity_silence_seconds`). Correction reports the silence duration and prompts `atdd agent escalate` if blocked.
- **`03-completion-claim-without-commit`** — fires on completion claims (`task complete`, `done`) when no commit has been observed. Correction: "You indicated completion but no commit was detected."
- **`04-out-of-scope-edit`** — fires when a file outside the WMBT target paths is modified, including the `.atdd/` clause absorbed verbatim from babysit's `detect_violation`. Correction: "You modified {path} not in WMBT scope. Revert or escalate."
- **`05-missed-heartbeat`** — fires when no `heartbeat.json` has been written for >M seconds (default per `observer.process_silence_seconds`). Correction: "Call `atdd agent heartbeat` after each significant action."
- **`08-reviewer-edit-attempt`** — fires when a reviewer-persona agent's output mentions edits or commits. Correction: "You are a Reviewer. You may not edit or commit."
- **`09-validator-failure-ignored`** — fires when a tier-1 validator failed on a prior commit and the agent commits again without addressing the cited rule_ids. Correction enumerates unaddressed rule_ids and their `fix_hint`s from `bind_rule()`.

Each rule:
- Resolves its `rule_id` via `bind_rule()` at load time.
- Carries a unit test with synthetic agent outputs demonstrating fire/no-fire (positive and negative fixtures).
- Produces correction records validating against `correction.schema.json` from #C0.

Rule-IDs introduced: seven canonical rule_ids per the §8.3 numbering. Schemas conformed to: `correction.schema.json`.

### Out of Scope

- Token-threshold rule `06-token-threshold` — #L3 owns it (separate issue because it absorbs three babysit functions verbatim).

- The dashboard and aggregate-approve operator surfaces — #L6 and #L7.
- Rule 07 (`07-llm-judge-on-commit`) is NOT in this issue — it is judge-related and lives in Track O (#O2), not in #L2's scope.

### Dependencies

- Existing repo: `bind_rule()` from the substrate; for rule 09, the `Violation` dataclass and the prior-commit `validations/<sha>/violations.jsonl` written by Track M.

## Context

### Problem Statement

| Aspect | Current | Target | Issue |
|--------|---------|--------|-------|
| Unstructured questions | Agents ask raw questions in chat instead of via `atdd agent ask --type` | Rule 01 detects free-form questions and redirects to the structured CLI | Without redirection, downstream judge/escalation paths cannot route the question correctly |
| Token silence | Stuck agents go undetected until an operator notices | Rule 02 fires on >90s silence with prompt to escalate | Without it, silent blocks waste wall-clock and operator attention is reactive only |
| Completion without commit | Agent claims `done` but the WMBT is not actually backed by a committed change | Rule 03 fires on completion-claim text with no recent commit | Without it, false-completion enters the review surface and burns reviewer time |
| Out-of-scope edits + .atdd/ hand-edits | Babysit's `detect_violation` catches the `.atdd/` clause but is hard-coded | Rule 04 generalizes to all WMBT-out-of-scope files and absorbs the `.atdd/` clause verbatim | Without observer-side detection, scope leaks reach review only |
| Missed heartbeats | Agent process alive but stuck → no signal | Rule 05 fires on stale `heartbeat.json` mtime | Heartbeat-based liveness is the cheap signal that complements token-based liveness (rule 02) |
| Reviewer edits | Reviewer persona is contractually no-write but no real-time guard exists | Rule 08 detects edit/commit-mentioning output from reviewer agents | Without it, accidental reviewer edits pollute the no-write contract |
| Validator failure ignored | Agent re-commits despite a prior tier-1 failure | Rule 09 cross-references prior `violations.jsonl` and fires when re-commit doesn't address the cited rule_ids | Without it, the tier-1/agent loop can spin on the same violation set |

### User Impact

The "user" is every coach-orchestrated agent — the rules in this issue are the protocol-level guardrails that turn implicit conventions into deterministic feedback. Per spec §8.5, observer rules are one layer of the compliance budget (alongside pre-commit, tier-1 validators, suppression scanner, tier-2 reviewer, AC coverage check, risk score). L2's seven rules close the basic-protocol layer.

After L2 lands, an agent that asks a free-form question gets nudged to use `atdd agent ask`; a stuck agent gets a silence prompt at 90s instead of waiting for human notice; a completion claim without a commit gets corrected before reaching review; a reviewer that drifts toward edits gets corrected immediately; an agent that ignores a tier-1 failure is told exactly which rule_ids and `fix_hint`s to address. Each rule is a feedback loop closed in observer-time rather than in human-time.

The lived observation: babysit's `detect_violation` already implements a subset of these (the `.atdd/` clause and `--status REFACTOR` SMOKE-skip). #L2 absorbs the `.atdd/` clause into rule 04 and lifts the rest into the extensible registry — same behavior, different substrate. Per spec §0.2, this is the absorption pattern: shipped behavior preserved, new behavior added.

### Design Anchor

The seven rules are bundled together because they share an evaluation surface — agent output, recent commit history, heartbeat state, persona context — and don't depend on substrate-specific machinery (suppression scanner, rule-id grammar) that #L5 needs. Splitting #L2 into seven sibling issues would multiply boilerplate without clarifying boundaries; bundling them as one PR matches the v3-spec's grouping.

Rule 04 deliberately absorbs babysit's `.atdd/` clause from `detect_violation` rather than re-deriving the predicate. Per spec §0.2, "the underlying functions … move from `commands/babysit.py` into observer-rule modules with no functional change."

Rule 09's correction text is rule-id-rich because the v3 spec calls out that reviewer findings reference rule_ids when applicable (§6.3) and that agent feedback gets fix_hints from `bind_rule()` (§7.6). The rule pulls fix_hints directly from the registry rather than synthesizing them.

## Acceptance

- `acc:observe-and-correct:M001-UNIT-001-rule-01-unstructured-question`: Rule `01-unstructured-question` fires on free-form question phrasing outside `atdd agent ask` and emits the §8.3 correction text; properly-formatted `atdd agent ask` invocations do NOT fire the rule.
- `acc:observe-and-correct:M001-UNIT-002-rule-02-token-silence`: Rule `02-token-silence` fires when no tokens have been observed for >90s and the correction reports the silence duration with `atdd agent escalate` guidance; below-threshold streams do not fire.
- `acc:observe-and-correct:M001-UNIT-003-rule-03-completion-without-commit`: Rule `03-completion-claim-without-commit` fires on completion claims without a recent `commit_observed` event; completion claims following a recorded commit do NOT fire.
- `acc:observe-and-correct:M001-UNIT-004-rule-04-out-of-scope-edit`: Rule `04-out-of-scope-edit` fires when a diff modifies a file outside the WMBT target paths or under `.atdd/` outside the allowlisted set (the absorbed babysit clause); behavior is at parity with `detect_violation`'s `.atdd/` clause for the absorbed cases.
- `acc:observe-and-correct:M001-UNIT-005-rule-05-missed-heartbeat`: Rule `05-missed-heartbeat` fires when `heartbeat.json` mtime is older than the configured threshold and prompts the agent to call `atdd agent heartbeat`; recently-touched heartbeats do not fire.
- `acc:observe-and-correct:M001-UNIT-006-rule-08-reviewer-edit-attempt`: Rule `08-reviewer-edit-attempt` fires when a reviewer-persona agent's output mentions edits or commits with the exact §8.3 correction text; non-reviewer personas with the same output do NOT fire this rule.
- `acc:observe-and-correct:M001-UNIT-007-rule-09-validator-failure-ignored`: Rule `09-validator-failure-ignored` fires when a prior `validations/<sha>/violations.jsonl` records failures and the new commit does not address the cited rule_ids; the correction text enumerates the unaddressed rule_ids and their `fix_hint`s pulled from `bind_rule()`.
- `acc:observe-and-correct:M001-UNIT-008-rules-co-located-as-yaml`: All seven rule files exist at `.atdd/observer/rules/<NN>-<slug>.yaml` (`01-unstructured-question.yaml`, `02-token-silence.yaml`, `03-completion-claim-without-commit.yaml`, `04-out-of-scope-edit.yaml`, `05-missed-heartbeat.yaml`, `08-reviewer-edit-attempt.yaml`, `09-validator-failure-ignored.yaml`) and each resolves to a canonical rule_id via `bind_rule()`.

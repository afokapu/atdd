## Scope

### In Scope

L5 implements four observer rules from spec §8.3 that depend on the substrate v12 alignment. Per spec §8.3, rules 10, 11, 12, and 17 are tier-2 bridge rules — they catch protocol-level issues before tier-1 validators flag them, shortening the feedback loop.

- **`10-stale-suppression-detected`**:
  - Fires when a commit touches a file containing `# atdd:suppress(<rule_id>) [UNTIL=<past>]` — toolkit conventions only.
  - Uses the existing substrate `find_stale_suppressions`.
  - Does **NOT** fire for `repo.*` rule IDs (substrate v12 §2: repo rules are unsuppressible).
  - Correction: `Stale suppression marker for {rule_id} found at {location} (UNTIL={date}, expired). Either fix the underlying violation or extend the deadline.`
- **`11-unbound-rule-id-in-validator`**:
  - Fires when an agent (typically tester or coder) creates a validator that emits a rule_id without a corresponding `bind_rule()` call at module-import time.
  - Correction references `SPEC-COACH-RULEID-0007` and the canonical rule_id.
- **`12-rule-id-grammar-violation`**:
  - Fires when an agent declares a rule with non-canonical-grammar `id` — anything not matching `<archetype>.<convention>.<rule>` per `SPEC-COACH-RULEID-0001`.
  - Correction directs the agent to use canonical form and place legacy IDs under aliases.
- **`17-repo-rule-disposition-declared`**:
  - Fires when an agent's diff adds `disposition:` to any acceptance or abuse_case YAML — substrate v12 §4.4 disallows this (repo rules are strict-by-construction; disposition is set by the walker, not declared).
  - Correction: `Repo contract rules cannot declare disposition (substrate v12 §4.4). Disposition is set by the walker to strict. Remove the field.`

Each rule is co-located at `.atdd/observer/rules/<NN>-<slug>.yaml` with unit tests covering positive (rule fires) and negative (rule does not fire) fixtures.

The `tester` archetype is on this issue (in addition to `coach`) because rule 11's predicate ("validator missing `bind_rule()`") inspects validator artifacts produced by the tester archetype, and rule 12's predicate inspects rule declarations the tester writes. Per spec §11.1 Track L row, this is a substrate-integration issue.

Rule-IDs introduced: four canonical rule_ids per the §8.3 numbering. Schemas: `correction.schema.json`. Substrate touchpoints: `find_stale_suppressions`, `bind_rule`, `RuleMetadata`.

### Out of Scope

- The other 13 default observer rules (#L1, #L2, #L3, #L4).
- Repo-rule strict-by-construction enforcement at the validator level — that is substrate v12 territory and ships there. #L5 implements the agent-time observer detection that catches violations earlier.
- The tier-1 validator dispatch — Track M owns it; #L5 is the tier-2 bridge that fires before tier-1 runs.
- Modifying the `SPEC-COACH-RULEID-0001` or `SPEC-COACH-RULEID-0007` grammars themselves — those are stable; #L5 enforces them.
- Suppression marker semantics changes — #L5 reads the existing markers via `find_stale_suppressions`; semantics are owned upstream.

### Dependencies

- `#L1` — observer skeleton and rule registry.
- Existing repo: substrate's `find_stale_suppressions`, `bind_rule()`, `RuleMetadata`; SPEC-COACH-RULEID-0001 (canonical grammar) and SPEC-COACH-RULEID-0007 (bind_rule contract); substrate v12 §2 (repo rules unsuppressible) and §4.4 (disposition not declared).

## Context

### Problem Statement

| Aspect | Current | Target | Issue |
|--------|---------|--------|-------|
| Stale suppression markers | Markers like `# atdd:suppress(<id>) [UNTIL=<past>]` accumulate silently and the underlying rule resurfaces only when someone runs the suppression scanner manually | Rule 10 fires on commit-time stale-marker detection (toolkit conventions only) | Without observer-time detection, debt drift is invisible until COMPLETE-time gating; with it, the agent gets feedback at commit-time |
| Repo rule unsuppressibility | Substrate v12 §2 declares repo rules unsuppressible, but no real-time signal corrects an agent that tries to suppress one | Rule 10 explicitly does NOT fire for `repo.*` IDs and the substrate validator catches the actual violation | The semantic distinction between toolkit conventions (suppressible) and repo rules (unsuppressible) needs observer-side reflection |
| Validators missing `bind_rule()` | An agent can author a validator that emits `Violation(rule_id=X)` without `bind_rule('X')` at module-import — discovered only by the SPEC-COACH-RULEID-0007 validator at PR-time | Rule 11 fires at commit-time when a new validator emits an unbound rule_id | Without it, the tester can ship a validator that the registry can't resolve |
| Non-canonical rule grammar | Legacy IDs like `SPEC-COACH-RULEID-1234` or freeform strings can sneak in as primary `id`s instead of being placed under `aliases` | Rule 12 fires at commit-time when a non-canonical primary id is declared | Without it, the rule-id grammar contract drifts and `bind_rule` lookups fragment |
| Repo rule disposition declaration | Agents editing WMBT/train/feature YAML can mistakenly add `disposition:` on an acceptance — substrate v12 §4.4 disallows this | Rule 17 fires at commit-time on the offending diff | Without it, the diff lands and the substrate walker silently overrides; agent never learns the contract |

### User Impact

The "user" is every coach-orchestrated agent (especially tester and coder personas) and the coach itself. Per spec §8.3, these four rules are tier-2 bridges: they catch protocol-level issues before tier-1 validators flag them, shortening the feedback loop. Without them, the same violations still get caught — but only at PR-time review or COMPLETE-time gating, which is much further from the moment of writing.

After L5 lands, an agent that adds a stale suppression marker gets feedback at commit-time; an agent that authors an unbound validator gets feedback at commit-time; an agent that uses non-canonical grammar gets corrected immediately; an agent that mistakenly declares disposition on a repo rule gets the substrate v12 §4.4 contract surfaced before the diff lands. Each rule shortens a feedback loop that already exists at the validator layer — observer-time detection does not replace tier-1, it precedes it.

The substrate-integration aspect is non-trivial: rules 10–12 and 17 each reference substrate machinery (`find_stale_suppressions`, `bind_rule`, the SPEC-COACH-RULEID grammar, substrate v12 §4.4). This issue is the explicit bridge between coach v9's observer surface and substrate v12's strict-by-construction repo-rule model.

### Design Anchor

Rule 10's **toolkit-only** scoping is a substrate v12 alignment, not a heuristic. Per substrate v12 §2, repo rules are strict-by-construction and suppression markers are ineffective on them. An observer rule that fired on a `repo.*` stale suppression would invite an operator to "fix" a marker that was never effective in the first place — which is exactly the wrong correction. The rule's negative-fixture (a `repo.*` stale marker NOT firing) is therefore a contract acceptance, not a side note.

Rules 11 and 12 are observer-time mirrors of validators that exist in the substrate (`SPEC-COACH-RULEID-0007`, `SPEC-COACH-RULEID-0001`). The substrate validators run at validate-time; the observer rules run at commit-time. The redundancy is intentional: observer-time feedback is the fast loop, validator-time enforcement is the strict floor.

Rule 17 is the closest to substrate v12 §4.4 — it catches the most common author error against the v12 disposition model and surfaces the spec citation directly in the correction text so the agent has a paper trail.
